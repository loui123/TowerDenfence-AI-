# 實作計畫

## 核心機制與平衡性修改

### 1. 連鎖專精檢查
- **出現條件修正**：調整 `isProjectileTower` 判斷邏輯，由判斷 `stats.type === 'projectile'` 改為直接檢查 `tower.type === 'projectile'`。
- **目的**：嚴格限制只有原生的弓箭塔（而不是砲擊、緩速塔等其他投射類塔）才能在升級選項抽選到「連鎖次數+1」，進而確保「連鎖彈射」專精只出現在合法的弓箭塔上，排除不合理的抽選情況。

### 2. 近戰塔重製
- **BOSS傷害加成與相關專精**：
  - 目前已經具備 `melee_boss_dmg` (頭目殺手) 升級，以及 `spec_tower_boss_killer` (巨獸行刑者) 專精。
  - **修復問題**：先前近戰塔的升級判定（`applyTowerUpgrade`）沒有攔截到 `melee_boss_dmg` 導致無法升級，現已修復。
  - **實作補完**：在 `GameEngine.js` 內的 `damageMob` 流程中，補上檢查 `mob.isBoss` 的乘區。如果有上述升級與專精，近戰塔對 Boss 將獲得正確的最終乘區加成。
- **多目標攻擊**：目前的系統架構中，近戰塔已預設為無限目標數 (`Infinity`)，且判定時會擴及整體攻擊範圍（範圍內所有目標），機制上已符合「每次攻擊範圍內所有目標」(AOE)。
- **基礎範圍提升**：在 `constants.js` 中將近戰塔預設攻擊距離（Range）由 3 提升為 2 格（先前後推至 4格，現已依需求修正為 2），並明確設定為 `aoe: true`。
- **流血機制改動**：
  - 流血描述更新為「可疊加」(Stackable)。
  - **已確認實作**：`target.bleedStacks` 設計為陣列，每次附加流血都會產生一包獨立的 Stack，並且單獨運算每層的持續時間與每秒出血傷害，本身就具備疊層並獨立計算跳傷的能力。同時，近戰塔在上屬性時，會立刻觸發一次當前疊層對應的瞬間破裂傷害。

### 3. 傷害公式調整與確認
- **傷害結構對齊**：
  - 公式設定為：`（「塔的基礎點傷」+「力量之書基礎點傷」 + 其他額外基礎 ）*（「天賦%傷」+其他%傷）`。
  - 在 `GameEngine.js` 裡的 `recalculateTowerDamage` 中，已確保：`flatBase = (overrideBase ?? baseDmg) + (mods.baseDamageBonus || 0) + powerBookBase + absorptionBase + magicBase`；而 %傷則加進 `pctMult` 中當作相乘放大係數。
  - **修復問題**：過往在獲得升級（`applyTowerUpgrade`）與抽選專精（`applyTowerSpecialization`）時，並未重算此公式，現已在對應函式結尾補上 `this.recalculateTowerDamage(tower)`，確保傷害即時轉換並精準吻合上述公式。
- **法術公式確認**：
  - 法術傷害的加成邏輯會正確讀取並套用 `GameEngine.js` 中的對應倍率乘除區。法術點傷也已經加入 `flatBase` 中計算，保證享有跟物理塔相同的一致性屬性增長公式（力量之書的點加成等也會被同樣放大計算入法術傷害中）。

## 美術替換 (2D Pixel Art)

- 遊戲中的視覺素材全面朝向 2D Pixel 像素風格邁進。已通過 AI 生成新素材。
- **單一靜態圖像**：已全面替換為各種防禦塔的專屬 Pixel Art 圖像（近戰、弓箭、緩速、砲擊、輔助、法術）。
- **影像去背與裁剪**：
  - 由於生成的動畫素材帶有純黑背景，遊戲內最初會有方塊黑底遮擋畫面。我們建置了專屬 Node.js 去背程式（`process_images2.js`），利用曼哈頓色彩距離與邊界洪泛填充演算法（Flood-Fill），將所有塔的圖片以及技能的背景完美轉換為透明（Alpha 0），並且進行緊湊裁剪，將影像邊界貼齊於網格大小。
- **多幀動畫用圖像**：
  - 目前已經順利匯入並實裝了「法術炎爆 (spell_1~4)」、「近戰刀光 (melee_hit_1~3)」、「箭矢命中 (proj_hit_1~3)」等連續像素動畫。
  - **修復問題（攻擊卡死）**：由於先前有部分動畫圖片未正確載入到遊戲目錄，導致繪圖引擎使用找不到圖片的 Canvas 繪圖產生例外錯誤（Crash/卡死）。已於 `Game.jsx` 中新增了 `img.complete && img.naturalHeight > 0` 防護機制嚴格確保圖片必須載入完成才能被繪製，徹底解決當機重製的問題。
  - **已知待辦（API 達到調用上限）**：關於「緩速塔」與「砲擊塔」的專屬攻擊動畫（冰霜特效、煙霧爆破），因為連續調用繪圖 AI 模型達到了今日最高額度（`Quota Exhausted: 429 Too Many Requests`，冷卻時間為 3.5 小時），因此並未完全生成。目前這些動畫已無縫銜接回舊版的 Canvas 原生幾何繪圖特效作為臨時備用支援，不會影響順暢度，日後解鎖即可立即補上專屬 Pixel Art。
